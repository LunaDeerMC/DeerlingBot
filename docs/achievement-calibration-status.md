## 算法

游玩时长只用于离线校准全服统一门槛；实际成就只看累计统计，不设置最低在线时长，不根据个人时长移动升级目标，也不在线自动重算全服门槛。

对每一类玩法，分位数仅使用该项大于零的参与者；计算总体达标率时包含零值玩家。

- **铜级：**1–10 小时参与者的第 35 百分位。
- **银级：**取「50–200 小时参与者中位数」与「10–50 小时参与者第 75 百分位」的较大值。
- **金级：**取「300 小时以上参与者第 80 百分位」与「50 小时以上参与者第 90 百分位」的较大值。

后两档加入其他时长组的下限，是为了避免“长时间在线但仅偶尔体验该玩法”的玩家把高级门槛压低。例如钓鱼在 50–200 小时组的正值中位数只有 16，而 10–50 小时组的第 75 百分位为 98；直接取前者会让银级过于接近体验奖励。该规则统一用于全部六类。

选择 300 小时而非 500 小时作为金级参考起点，是为了兼顾长期目标和可达性，并增加样本。它属于明确的玩法设计选择，不是统计能唯一推导出的“正确答案”。金级参考组包含 44 份记录，各玩法正值样本为 33–44；它们仍不算大型样本。

每个基础组和下限组均要求至少 20 个正值样本，本次全部满足。分位数采用 `(n - 1) × p` 位置的线性插值；取较大值后，按两位有效数字四舍五入（半值向上），最终使用整数次数或整数公里。因此钓鱼银级为 98，交易银级为 390。

用户反馈首次铜级候选偏低，要求适度提高。最终铜级在算法候选基础上提高约 60–67%：挖掘 300→500、合成 180→300、飞行 5→8 km、钓鱼 3→5、交易 15→25、步行 3→5 km；银级和金级沿用算法值。这一步是明确的玩法调整，不冒充算法直接输出。下列默认值和达标比例已按调整后的配置重新计算。

样本不足、不递增、超过原版统计范围时，工具明确报告，不补猜测值、不静默外推。当前门槛已全部通过检查。

铜级调整使 1–10 小时组至少获得一项铜级成就的比例从 83.4% 降为 68.5%。细分来看，1–2 小时为 60/146（41.1%）、2–5 小时为 118/140（84.3%）、5–10 小时为 66/70（94.3%）。10–50 小时组仍全部至少获得一项铜级成就。

- 配置功能实现时 184 项 Java 回归测试通过；本次提高铜级后重新运行相关的 22 项配置、模型、统计读取和重载测试，全部通过，包含配置补齐、六类自定义值、厘米转换、错误重载保留旧值和原有进度边界。
- 用编译后的真实 `PlayerCardProfile` 模型重放 1,796 份匿名汇总统计，逐类核对 18 个等级达标总数，与独立 Python 按最终配置回算的结果完全一致；默认值与金级成就数量分布也一致。
- 离线工具验证了基础组或下限组缺样本时不给候选值；原来三个 UI 样本不能用于全服校准。
- 一个鞘翅统计已经达到原版 int 上限，未删除该记录；最终飞行门槛 5,100 km 远低于约 21,474.84 km 的可记录上限。

离线工具只依赖 Python 标准库，不读取服务器、不发送请求、不修改插件配置：

```sh
python3 tools/calibrate_achievements.py /private/anonymous-stats.json --output /private/final-calibration.json
python3 tools/calibrate_achievements.py /private/anonymous-stats.json --evaluate-thresholds /private/thresholds.json
```

输入为匿名 JSON 数组或 JSONL，每条包含整数 `played_ticks`、`mining`、`crafting`、`elytra_cm`、`fishing`、`trading`、`walking_cm`。输入必须已经按权威存档目录去重，输出仅保留汇总分布。

工具默认输出统计候选，不包含用户反馈后的铜级调整。复现最终默认配置时，将上方 YAML 的 `achievement-thresholds` 段转为 JSON 传给 `--evaluate-thresholds`，查看 `supplied_threshold_evaluation`；`complete_candidate_evaluation` 保留未经玩法调整的候选结果。

时间窗口、分位数和最小样本量属于设计参数，应随玩家群体变化重新审阅；固定三档累计体系不能保证老玩家永不满级。不能把“当前累计数量 ÷ 在线时间”称为真实解锁耗时，也不能把上述横截面比例称为新人未来解锁概率。
